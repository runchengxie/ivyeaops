# eMAG 带来源的运营检查与记录

[English](../emag-playbooks.md)

结构化检查面板用于处理已有库存的问题、准备本地修改方案，并保存人工判断的依据。面板接入 eMAG 的 Listing、打法和分析工作区。保存记录不会提交商品资料、合并变体、充值广告、采购或创建入仓单。

## 可以记录什么

| 工作流 | 输入与结果 | 适用范围 |
|---|---|---|
| 审核修复指引 | 当前快照异常、相关检查项和教程出处 | 指引不等于已核实根因，也不执行平台动作 |
| Listing 检查 | 商品事实、语言、类目与合同、特征、图片和条码的人工核对 | 缺失项保持未知，不自动认证图片或法规合规 |
| 变体方案 | 已有商品 ID、差异值及共用 Family 信息 | 成员仍需人工确认，不远程合并 |
| 竞品观察 | 来源链接、观察时间、含税价格、规格和配送条件 | 不能据此推断销量、市场需求或推荐售价 |
| 广告复盘 | Campaign 和 Adset 状态、前提条件及可选的期间数据 | 人工记录，不充值、激活、出价或声称盈利 |
| 入仓装箱 | 入仓号、地址人工确认、箱号、数量及条码 | 不预设现行仓库地址，不提交入仓申请 |
| 成本依据 | 计算器字段、数值及单位、来源、观察时间、有效期和范围 | 单独保存，不更新或核实成本计算器 |

新面板默认使用英语，可显式切换为中文并保存选择。这个切换只覆盖新面板，不代表整个产品已完成国际化。

## 建议先做的一轮工作

1. 在打法工作区选择店铺最新导入的快照，优先查看有库存且存在可售或资料异常的商品。
2. 阅读平台异常和关联教程，再去卖家后台核实具体原因。
3. 填写商品事实，只确认已有依据的检查项。检查失败就保留失败，不能为了让记录看起来完整而改成未知。
4. 保存本地版本。实际人工操作继续使用已有草稿和处理记录流程，保存检查单不会推进批准或执行状态。
5. 人工处理后重新采集，再按新快照复查。旧记录保留旧来源版本，不能视为对新快照的确认。

## 如何理解检查结果

勾选和数字记录的是操作者的陈述，不是平台审核、实际收货、退款支付或广告归因的证明。检查通过只表示提交的数据满足该项条件。缺失不能变成零。图片和条码检查明确属于人工核对，旧教程中的图片尺寸、EAN 示例和费用不固化为现行规则。

广告指标需要有效的起止期间。CPC 需要已知花费和非零点击，ROAS 需要已知收入和非零花费。ROAS 仅是录入数字的比值，不是会计利润。Campaign 与 Adset 状态分别记录，数据期间和归因口径需要操作者核对。

成本依据应对应现有计算器的具体字段，注明单位、来源、观察时间、有效期和适用范围。需要另外比较依据数值与计算器已保存输入。旧选品表中未解释的系数不能直接当作现行 VAT、佣金或汇率规则。

## 保存位置与权限

管理员接口读取不可变店铺快照，本地记录保存于配置的 `IVYEA_OPS_DATA_DIR`。每个版本绑定店铺、快照、商品和已认证操作者。更新需要当前记录版本和当前快照，冲突或过期请求会被拒绝，不覆盖他人的操作。历史版本保留，每页最多 500 条，通过 `before_sequence` 读取更早记录，`records_next_before` 提供下一页游标。只有全局最新且绑定当前快照的记录才是当前版本。这些接口不调用平台写入能力。

- `GET /api/emag/stores/{store_id}/playbooks`
- `POST /api/emag/stores/{store_id}/playbooks/records`

私有观察、备注和培训原件放在 Git 以外，使用项目已有方法备份应用数据目录。培训原件目录与应用记录库相互独立，不会自动上传。

## 教程来源与时间

来源目录保存简要说明和文档页码定位。资料包括类目申请、单个与批量上架、竞品价格比较、FBE 装箱、标注 2024 年 7 月的广告课件，以及没有完整解释费用假设的卖家选品表。无法确定的日期保持未知。引用说明检查项从哪里来，不证明它符合当前官方要求。

PDF、PPTX、工作簿及在线文档快照继续保存在私有目录。定位信息应能对应原件标题及页码、幻灯片页序或工作表。公共仓库不保存个人机器路径、私有分享 token 或原件。视频目录背后的外部课程和无法读取的补充附件不作为规则依据。
